## 1. 范围与目录约定（来自 02 §P-6）

| 层 | 覆盖 | 目录 | 工具 |

```text
tests/

```

**夹具要求**：接口级测试用**独立的临时库**（`ragdemo_test`，跑前建、跑后删），不碰 `ragdemo`；LLM 调用在测试里**必须打桩**（除 AC-5/AC-6 的手工验收），避免产生真实费用。

## 2. 验收项映射（AC-1 ~ AC-13）

| 用例 | 类型 | 前置 | 步骤 | 断言 | AC |
| --- | --- | --- | --- | --- | --- |
| TC-01 | api | 空库 | `POST /documents/upload` 传含文字 PDF | `code="ok"`、`data.items[0].status="success"`、`chunks>0`、`overwritten=false`；`GET /documents` 出现该文档且 `chunk_count>0` | AC-1 |
| TC-02 | api | 已存在同名文档 | 再传同名但内容不同的 PDF | `overwritten=true`、`document_id` 不变、`chunk_count` 更新；列表仍 1 条且排首位（`updated_at` 最大）；旧内容检索不到 | AC-2 |
| TC-03 | api | 空库 | 同一请求传 `.exe` + 正常 PDF（分两次调用：先 .exe 后 PDF） | `.exe` → `status="failed"`、`error.code="UNSUPPORTED_FILE_TYPE"`；列表不含它；PDF 正常入库 | AC-3 |
| TC-04 | api | 有 1 份文档 | `DELETE /documents/{id}` → `GET /documents` → 提问该文档内容 | 删除返回 200 + `data:null`；列表移除；检索不再命中；`data/uploads/` 下原文件已删 | AC-4 |
| TC-05 | api（打桩 LLM） | 有命中文档 | `POST /chat`，读取 SSE 流 | 先收 `citations`（≥1 项，`n` 从 1 连续），再收 ≥2 个 `delta`，最后 `done` 且带 `conversation_id`；拼起来含 `[1]` | AC-5 |
| TC-06 | api | 空库 | `POST /chat` | **无** `citations` 事件；`delta` 文本 = 固定话术；`done` 带 `conversation_id`；`GET /conversations` 新增 1 条（Q7 无结果也存） | AC-6 |
| TC-07 | api | 有 1 条历史 | `GET /conversations` → `GET /conversations/{id}` | 列表含该条（标题 ≤30 字）；详情含 2 条消息（user 在前）、`citations` 结构完整 | AC-7 |
| TC-08 | api（Key 置空） | 有命中文档 | `POST /chat` | 收到 `error` 事件（`code="LLM_KEY_MISSING"`）；`GET /conversations` 数量不变（不产生空历史） | AC-8 |
| TC-09 | api | 空库 | 上传 `files` 文件名为 `..\..\evil.pdf` | `status="failed"`、`error.code="INVALID_FILENAME"`；`data/uploads/` 外无新文件 | AC-9 |
| TC-10 | api | 已入库若干文档 | 重启服务进程后 `POST /chat` | 检索正常返回（BM25 从库重建）；**无需**任何手工建索引 | AC-10 |
| TC-11 | api | — | `POST /chat` 传 `""`、`"   "`、501 字 | 422 且 `code` 分别为 `QUESTION_EMPTY` / `QUESTION_EMPTY` / `QUESTION_TOO_LONG` | AC-11 |
| TC-12 | api | 空库 | 上传带表头的 xlsx | `status="success"`、`chunks>0`；用"列名: 值"形式的片段可被检索命中 | AC-12 |
| TC-13 | api | 空库 | 上传 0 字节文件 | `status="failed"`、`error.code="EMPTY_FILE"`；列表不含；`data/uploads/` 无临时文件残留 | AC-13 |

## 3. 边界与异常（AGENTS §8.1 要求补齐）

| 用例 | 类型 | 场景 | 断言 |
| --- | --- | --- | --- |
| TC-14 | api | 单次请求传 2 个文件 | 422 `TOO_MANY_FILES`，一个都不处理 |
| TC-15 | api | 单文件 51 MB | 该文件 `status="failed"`、`error.code="FILE_TOO_LARGE"`；服务不崩 |
| TC-16 | api | `Content-Length` 超过 55 MB | 413 `PAYLOAD_TOO_LARGE`，不读 body、不落盘（04 V-8） |
| TC-17 | api | 扩展名大写 `.PDF` | 接受（白名单大小写不敏感） |
| TC-18 | api | 不存在的 `document_id` / `conversation_id` | 404，`code` 分别为 `DOCUMENT_NOT_FOUND` / `CONVERSATION_NOT_FOUND` |
| TC-19 | api | 路径参数 `abc` / `0` | 422 `VALIDATION_ERROR` |
| TC-20 | api | 数据库停机后 `GET /documents` | 503 `DB_UNAVAILABLE`；`GET /health` 仍 200 且 `status="degraded"`、`database="error"` |
| TC-21 | api（打桩超时） | LLM 不返回首字节超过 15 s | 收到 `error` 事件 `LLM_TIMEOUT`；无历史写入 |
| TC-22 | api | 上传过程中客户端断开 | 服务端停止处理、不落库、不留临时文件 |
| TC-23 | api | SSE 生成中断开连接 | 停止生成、不保存历史 |
| TC-24 | unit | 切分：短文本（≤ size） | 不切分，原样返回 1 块 |
| TC-25 | unit | 切分：超长单句（> size 且无标点） | 硬切，每块 ≤ size |
| TC-26 | unit | BM25：检索后上传新文档 | 索引置失效，下次检索前重建，新内容可命中（BR-4） |
| TC-27 | unit | RRF：两路结果有重叠 | 融合去重，`top_k=5`，顺序稳定 |
| TC-28 | api | 上传导致同名覆盖失败（打桩向量化抛错） | 旧文档、旧片段、旧原文件全部保持原样（BR-2） |
| TC-29 | api | 删除时原文件已被手工删除 | 仍返回 200，文档记录正常删除 |
