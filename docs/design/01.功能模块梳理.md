## 1. 文档说明

### 1.1 目的

在不引入新技术决策的前提下，把 SRS 的功能需求与原型中的交互行为，收敛成**功能清单 + 模块划分 + 模块关系 + 业务流程**，作为后续架构设计的输入。

本文回答四个问题：

1. 系统要做哪些功能？（第 2 节）
2. 这些功能归哪些模块，各自职责边界在哪？（第 3 节）
3. 模块之间怎么协作？（第 4 节）
4. 主流程怎么走，异常怎么分支？（第 5 节）

### 1.2 范围

**本文包含**

- 功能清单与需求来源映射（FR / BR / AC → 功能）
- 功能模块划分、职责、边界（做什么 / 明确不做什么）
- 模块依赖关系与交互清单
- 四条核心业务流程（上传、删除、问答、历史）
- 尚不明确的问题与候选方案（第 7 节）
- 已知缺口登记与销项位置（第 9 节）

**本文不涉及**（按本轮任务要求排除）

| 排除项 | 说明 |
| --- | --- |
| 技术选型 | 框架、库、模型、部署形态一律不在此定 |
| 数据库设计 | 表结构、字段、索引、迁移方案不在此定 |
| API 接口设计 | 路径、方法、请求响应格式、错误码不在此定 |
| 代码开发 | 不写实现，不重构现有代码 |
| 新增功能 | 只做已有需求与原型的功能归纳；原型中超出 SRS 的行为一律列为待确认，不自动纳入范围 |

### 1.3 术语

沿用 [SRS 1.3](../SRS.md#13-术语)，补充三个本文用到的词：

| 术语 | 说明 |
| --- | --- |
| 模块 | 一组高内聚的功能职责，有明确边界和对外能力 |
| 功能域 | 若干相关模块的集合（知识库域 / 问答域 / 历史域 / 系统域） |
| 支撑能力 | 不直接面向用户、被其他模块调用的能力（如检索、引用组装） |

## 3. 模块划分

### 3.1 划分原则

1. **按职责内聚，不按代码分层。** 本文不做技术分层（那是架构阶段的事），只按「一组功能该由谁负责」来切。
2. **一个功能只归属一个主责模块**，其他模块参与时标为「参与」。
3. **模块边界写「不做什么」**，避免后续设计时职责蔓延。
4. **支撑能力单独成模块**（检索、引用），便于被多个上层模块复用。

### 3.2 模块总览

```text
                          ┌──────────────────────────┐
                          │   界面呈现层 UI（横切）     │

        ┌──────────────┬───────────────┼────────────────┬──────────────┐
        ▼              ▼               ▼                ▼              ▼
  ┌───────────┐  ┌───────────┐  ┌───────────┐   ┌───────────┐  ┌───────────┐
  │M1 文档管理 │  │M4 问答生成 │  │M6 会话历史 │   │M7 系统状态 │  │           │
  └─────┬─────┘  └─────┬─────┘  └─────┬─────┘   └───────────┘  │           │
        │              │              │                        │           │
        ▼              ▼              │                        │           │
  ┌───────────┐  ┌───────────┐       │                        │           │
  │M2 入库流水线│  │M3 检索引擎 │       │                        │           │
  └─────┬─────┘  └─────┬─────┘       │                        │           │
        │              │              │                        │           │
```

### 3.3 模块职责详述

#### M1 文档管理（知识库域）

**职责**：文档生命周期的入口与出口——让用户把文件"送进来"和"删出去"，并让用户看到知识库当前有什么。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-01、F-02、F-06、F-07、F-08、F-09、F-10、F-11 |
| 输入 | 用户选择的文件列表；删除指令（文档标识 + 确认） |
| 输出 | 逐文件处理结果（成功 / 失败原因 / 是否覆盖 / 片段数）；文档列表；删除结果 |
| 依赖 | M2（把文件变成知识片段）、M3（删除后使检索感知变化） |
| **不做什么** | 不做解析、切分、向量化（M2）；不做检索打分（M3）；不负责回答内容（M4） |

**关键职责点**

1. 前置校验在**进入流水线之前**完成，校验不通过的文件不进入 M2。
2. 上传结果**逐文件**呈现，不允许"整批一个结果"。
3. 列表只包含入库成功的文档；失败文档仅出现在上传结果中（SRS FR-2）。
4. 删除必须二次确认，且文案明确"不可恢复"。

---

#### M2 文档入库流水线（知识库域）

**职责**：把一份文件确定性地转换成可被检索的知识片段，并保证"要么全成、要么不留痕迹"。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-03、F-04、F-05 |
| 输入 | 已通过前置校验的单个文件 |
| 输出 | 该文件的知识片段、片段数、是否覆盖原有同名文档 |
| 依赖 | M3（写入后让检索索引感知到变化） |
| **不做什么** | 不决定结果怎么展示（M1）；不判断文件是否该收（M1 已校验）；不做检索（M3） |

**关键职责点**

1. 处理链固定为四步：解析 → 切分 → 向量化 → 写入；**任一步失败即整体失败**。
2. 失败时不写库、不保留原文件（SRS FR-1、BR-10）。
3. 同名覆盖必须与原数据保持一致：覆盖失败要能回到覆盖前的状态（详见第 7 节 Q1）。
4. 一份文档入库后，检索侧必须能立即检索到它（涉及索引刷新职责，见第 7 节 Q1 之外的技术问题，本文不定）。

---

#### M3 检索引擎（问答域，支撑能力）

**职责**：把一个问题变成"有依据的候选资料"，并给出明确的"有 / 无"结论。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-13、F-14、F-15（判定部分）、F-11（删除后的不可见性） |
| 输入 | 用户问题文本 |
| 输出 | 融合后的前 5 条资料（含来源、位置、片段内容）；或"无结果"结论 |
| 依赖 | 知识片段集合（由 M2 写入、M1 删除） |
| **不做什么** | 不生成任何文本；不做查询改写、不拼历史上下文（本期明确不做）；不做 rerank（本期不做） |

**关键职责点**

1. 两路召回各取 20，融合取 5——参数集中可配（SRS NFR-6）。
2. 两路均空才判定"无结果"；只要有一路有结果就继续走 M4。
3. 检索范围是整个知识库，本期不支持按文档筛选。

---

#### M4 问答生成（问答域）

**职责**：在给定资料的前提下，产出有依据、可追溯、流式呈现的中文回答。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-12（后端侧约束）、F-15（兜底话术）、F-16、F-17、F-18 |
| 输入 | 用户问题 + M3 给出的资料 + M5 给出的编号 |
| 输出 | 增量文本流；结束信号；错误信号 |
| 依赖 | M3（资料）、M5（编号）、外部大模型服务 |
| **不做什么** | 不检索（M3）；不渲染引用卡片（M5）；不保存历史（M6）；不做多轮上下文 |

**关键职责点**

1. 回答约束由系统提示词固化：只用资料、不编造、资料不足直接说"根据已有资料无法回答"、用 `[n]` 标注、中文。
2. 无资料时不调用大模型，直接返回固定话术（BR-6）。
3. 生成过程必须可增量输出，且客户端断开时停止生成（SRS 7.4）。
4. 生成失败**不产生空的历史记录**（SRS FR-6 规则）。

---

#### M5 引用来源（问答域，支撑能力）

**职责**：把"资料"翻译成"用户能对上号的引用条目"，并保证编号与回答中的 `[n]` 严格一致。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-19、F-20 |
| 输入 | M3 给出的资料列表 |
| 输出 | 引用条目列表：序号、文件名、位置、片段摘要（前 100 字，超出省略） |
| 依赖 | 资料本身（来源、位置、内容） |
| **不做什么** | 不支持点击展开完整片段（本期不做）；不判断回答是否真的引用了某条（该判定若要做，见第 7 节 Q6） |

**关键职责点**

1. 编号在**提供资料给大模型之前**就确定，生成过程不得改变编号。
2. 引用条目要能作为快照被历史保存（M6 依赖），因此必须是自包含的（见第 7 节 Q2）。
3. 位置展示规则：PDF 显示页码；无页码文档及表格类文档统一显示"全文"（Q9 已确认）。

---

#### M6 会话历史（历史域）

**职责**：让每次问答留痕，并能被回看与删除。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-21、F-22、F-23、F-24、F-25、F-26 |
| 输入 | 一次问答的完整结果（问题、回答、引用快照） |
| 输出 | 历史列表；单条会话详情；删除结果 |
| 依赖 | M4、M5（问答结果） |
| **不做什么** | 不做多轮上下文拼接；不重新调用大模型（回看时）；不保存失败的空回答 |

**关键职责点**

1. 会话标题取问题前 30 字，超出省略。
2. 回看是**只读**操作，不得触发检索或生成。
3. 删除会话时级联删除其消息。
4. 刷新页面 / 重启服务后历史仍在（持久化要求）。

---

#### M7 系统状态（系统域）

**职责**：让用户知道"现在能不能用、为什么不能用"。

| 项 | 内容 |
| --- | --- |
| 覆盖功能 | F-27、F-28 |
| 输入 | 数据库连通性、嵌入模型加载状态、大模型 Key 配置状态 |
| 输出 | 整体状态（正常 / 降级）与分项状态 |
| 依赖 | 无（读取各依赖的当前状态） |
| **不做什么** | 不做自动恢复、不做重试；不替代错误提示（M4/M1 各自负责） |

---

### 3.4 横切：界面呈现层（UI）

**定位**：不是业务模块，而是所有模块的展示出口。只消费能力，不做业务判断。

| 职责 | 说明 |
| --- | --- |
| 布局 | 顶部导航（问答 / 知识库）、左侧历史侧边栏、右侧主内容区 |

### 4.1 依赖方向

```text
UI ──► M1 ──► M2
 │      └─────► M3（删除后使检索结果变化）
```

## 5. 核心业务流程

> 说明：以下流程只描述**功能级**步骤（谁在什么时机做什么、用户看到什么），不涉及接口形态与存储细节。

### 5.1 文档上传入库流程

> 粒度（Q3 已确认）：前端**逐文件提交**，每个文件独立走一次「校验 → 处理 → 结果反馈」；单个文件失败不影响同批其他文件。

```text
用户选择/拖拽文件
   │
   ├─► M1 前置校验（逐文件）
   │      ├─ 扩展名不在白名单 ────────► 该文件失败：提示支持的格式
   │      ├─ 超过 50 MB ─────────────► 该文件失败：提示大小上限
   │      ├─ 空文件 ─────────────────► 该文件失败：提示文件为空
   │      └─ 文件名含路径分隔符/.. ───► 该文件失败：提示非法文件名
   │
   ├─► 校验通过 ──► M2 处理链
   │      ├─ 解析（无文字层 / 表格无有效行）
   │      │     └─ 失败 ──► 整体失败：不写库、不落盘
   │      ├─ 切分
   │      ├─ 向量化 ──► 失败 ──► 整体失败：不写库、不落盘
   │      └─ 写入
   │            ├─ 同名存在 ──► 一次性替换旧数据（新数据就绪后才动旧数据）
   │            │      └─ 替换失败 ──► 旧文档与旧原文件保持原样，报告失败
   │            └─ 同名不存在 ──► 新增
   │
   ├─► M3 感知变更（新文档立即可被检索）
   │
   └─► M1 汇总结果 ──► UI 逐文件展示 + 刷新文档列表与统计
```

**分支与结果**

| 场景 | 用户可见结果 |
| --- | --- |
| 全部成功 | 每个文件一行"上传完成"+ 片段数；列表新增；统计更新 |
| 部分失败 | 失败文件行显示原因；成功文件正常入库；列表只出现成功项 |
| 同名覆盖成功 | 该文件行显示"已覆盖同名文档"；列表仍为一条，片段数更新 |
| 同名覆盖失败 | 该文件行显示失败原因；旧文档与旧原文件保持不变 |
| 整批超过 20 个 | **整批拒绝**：提示超出上限，本次一个文件都不处理（Q8 已确认） |

### 5.2 文档删除流程

```text
用户点击文档行的删除
   │
   ├─► 弹出二次确认，文案说明"片段与原文件一并删除、不可恢复"
   │      └─ 取消 ──► 关闭弹窗，无任何变化
   │
   ├─► 确认 ──► M1 删除
   │      ├─ 文档不存在 ──► 接口 404；前端按"已删除"友好提示，不展示错误态
   │      ├─ 原文件已被手动删除 ──► 仍删除记录，返回成功
   │      ├─ 删除失败 ──► 提示失败，保持原状态一致
   │      └─ 成功 ──► 删除全部知识片段 + 原文件
   │
   ├─► M3 感知变更（该内容不再被检索命中）
   │
   └─► UI 刷新列表与统计 + Toast
```

### 5.3 问答流程

```text
用户输入问题 → 提交
   │
   ├─► 前端校验：空 / 超过 500 字 ──► 阻止提交并提示
   │
   ├─► M3 检索
   │      ├─ 两路均空
   │      │     ├─ 知识库为空 ──► 固定话术（不调用大模型）
   │      │     └─ 有文档但无命中 ──► 固定话术（不调用大模型）
   │      │
   │      └─ 有结果 ──► M5 生成引用（确定编号）
   │                           │
   │                           ▼
   │                     M4 调用大模型（带编号资料）
   │                           ├─ 流式增量 ──► UI 边生成边显示
   │                           ├─ 成功 ──► M6 保存会话（问题 + 回答 + 引用快照）
   │                           └─ 失败 ──► 终止流 + 错误提示 + 可重试；不保存空历史
   │
   └─► UI 结束后启用输入框
```

**分支与结果**

| 场景 | 用户可见结果 |
| --- | --- |
| 有资料、生成成功 | 流式回答 + 引用卡片；侧边栏新增一条历史 |
| 有资料、生成失败 | 错误提示 + 可重试；**不产生**历史记录 |
| 无资料 | 固定话术；不产生大模型调用；**仍保存历史**（Q7 已确认） |
| 知识库为空 | 固定话术 + "去上传文档"引导按钮 + 欢迎页示例问题（Q10 已确认） |
| 问题为空 / 超长 | 前端阻止；直接调用接口时应返回明确错误 |

### 5.4 历史回看与删除流程

```text
打开页面 ──► M6 拉取历史列表（时间倒序）──► 侧边栏渲染
   │
   ├─► 点击某条 ──► M6 读取会话详情 ──► UI 渲染问题 / 回答 / 引用卡片
   │                 └─ 只读：不检索、不调用大模型
   │
   ├─► 点击新建对话 ──► 清空视图，回到欢迎页（不创建空会话）
   │
   └─► 点击删除 ──► 二次确认 ──► 删除会话及其消息 ──► 刷新列表 + Toast
                     └─ 若删除的是当前正在看的会话 ──► 回到欢迎页
```

### 5.5 流程中的状态与用户反馈

| 状态 | 触发 | 用户可见反馈 |
| --- | --- | --- |
| 上传中 | 文件进入 M2 | 队列行显示阶段文案（解析 / 切分向量化 / 写入） |
| 上传失败 | M2 任一步失败或前置校验失败 | 队列行标红 + 原因 |
| 检索中 | M3 执行 | 输入框禁用，显示"正在检索知识库" |
| 生成中 | M4 流式输出 | 增量文本 + 光标；输入框禁用 |
| 生成失败 | 大模型异常 | 错误提示 + 重试入口 |
| 模型冷启动 | 首次加载嵌入模型 | 顶部或输入框提示"模型加载中" |
| 知识库为空 | 文档数为 0 | 顶部状态显示"知识库为空" + 空状态引导 |

## 6. 关键概念与状态定义

### 6.1 文档

| 状态 | 含义 | 何时出现 |
| --- | --- | --- |
| 处理中 | 正在解析/切分/向量化 | 已通过前置校验，尚未完成入库 |
| 可用 | 已入库，可被检索 | 入库成功 |
| 失败 | 处理链失败 | 不入库、不落盘、只在上传结果中出现 |

> 注（Q4 已确认）："可用"是概念状态，**不作为列表字段**展示；能出现在列表中即代表可用。SRS AC-1 措辞据此修订。

### 6.2 会话与消息

| 概念 | 定义 |
| --- | --- |
| 会话 | 一次提问及其回答的记录；标题取问题前 30 字 |
| 用户消息 | 问题原文 |
| 助手消息 | 回答正文 + 引用快照 |
| 引用快照 | 生成时确定的引用条目（序号/文件名/位置/摘要），随消息一起保存 |

> 已确认（Q2）：引用为**自包含快照**，随消息永久保存；删除文档不影响历史中的引用展示，也不做「已删除」标记。

### 6.3 引用条目

| 字段 | 规则 |
| --- | --- |
| 序号 | 与提供给大模型的资料编号一致，从 1 开始 |
| 文件名 | 原始文件名 |
| 位置 | PDF 显示页码；其他无页码文档及表格类文档统一显示"全文" |
| 摘要 | 片段前 100 字，超出以省略号截断 |

## 7. 待确认问题

> 按阻塞程度分级：**P0** 影响核心流程语义；**P1** 影响验收与体验一致性；**P2** 细节与可选项。

### 7.0 已确认决策

| 编号 | 决策 | 确认日期 |
| --- | --- | --- |
| Q1 | 同名覆盖：先完成新数据准备，再一次性替换旧数据；任一步失败则旧数据完全不受影响 | 2026-11-01 |
| Q2 | 引用条目为自包含快照，随消息永久保存；删除文档不影响历史展示 | 2026-11-01 |

| Q6 | 引用卡片统一展示"引用来源"，本期不做"参考"标注，也不判定是否被引用 | 2026-11-01 |

### Q1【已确认】同名覆盖的处理顺序与失败语义

- **出处**：SRS [FR-1 处理步骤 3/4](../SRS.md#fr-1-文档批量上传) 与 [BR-2](../SRS.md#9-业务规则)
- **冲突点**：FR-1 说"在同一事务中删除旧 chunk、写入新 chunk"，BR-2 说"先删除旧 chunk 与旧原文件，再写入新数据；失败保留旧数据"。前者是先算后写，后者是先删后写——两条对"覆盖过程中旧数据是否存在"的描述不一致。
- **结论（2026-11-01）**：采用 **A**——解析、切分、向量化全部成功后，才一次性替换旧数据（旧片段 + 旧原文件）；任一步失败，旧文档与旧原文件保持原样，不产生半成品。
- **连带影响**：BR-2 中"先删后写"的表述作废，需同步修订 SRS；M2 的职责收敛为「先就绪、后替换」，覆盖期间不出现空窗。

### Q2【已确认】删除文档后，历史记录中的引用怎么处理

- **出处**：SRS 未覆盖；FR-6 只说"点击历史项回看完整问题、回答与引用"
- **冲突点**：引用条目包含文件名与片段摘要，但文档被删除后，这些信息是否还应展示，SRS 没有规定。
- **结论（2026-11-01）**：采用 **A**——引用为自包含快照，随消息保存；删除文档不影响历史展示，也不做"已删除"标记。
- **连带影响**：M5 的输出必须自包含（不得只存文档标识），M6 保存的是引用快照而非引用指针。

### Q3【已确认】上传批次的语义：整批一次 vs 逐文件

- **出处**：SRS [7.1](../SRS.md#71-上传文档)"服务端按顺序处理；前端也可逐文件调用以展示进度"；FR-1 界面要求"允许取消未开始的文件（可选）"
- **影响**：决定上传进度的粒度、"取消未开始文件"是否可实现、单文件失败的重试方式。
- **结论（2026-11-01）**：采用 **A**——前端逐文件提交，后端一次只处理一个文件；进度按文件粒度呈现，未开始的文件可取消。
- **连带影响**：上传结果天然是「逐文件」结构，部分成功无需额外设计；单个失败文件可直接重试。5.1 流程按此粒度细化。

### Q4【已确认】文档列表是否需要「状态」列

- **出处**：SRS [AC-1](../SRS.md#10-验收标准)"列表出现该文档，状态'可用'"；对照 [FR-2 字段](../SRS.md#fr-2-文档列表) 与原型表格，**均无状态列**
- **影响**：验收标准与界面字段不一致，需要统一口径。
- **结论（2026-11-01）**：采用 **A**——列表不设状态列；能出现在列表中即代表可用。
- **连带影响**：SRS AC-1 措辞需改为"列表中出现该文档，片段数 > 0"，删去"状态'可用'"的表述。

### Q5【已确认】列表时间字段与排序依据

- **出处**：SRS [FR-2](../SRS.md#fr-2-文档列表)"按上传时间倒序"、字段含"上传时间"；原型表头为"最近更新"，排序用的是更新时间
- **影响**：同名覆盖后，该文档在列表中的位置会变化与否；验收 AC-2 的描述也受影响。
- **结论（2026-11-01）**：采用 **A**——列表按"最近更新"倒序，展示的也是最近更新时间；同名覆盖后该文档浮到列表顶部。
- **连带影响**：SRS FR-2 的"上传时间"措辞需改为"最近更新时间"，AC-2 的预期结果据此描述。

### Q6【已确认】「未实际引用的资料标注为参考」是否本期要做

- **出处**：SRS [FR-5](../SRS.md#fr-5-引用来源)"回答中未实际引用的资料可仍列出，但需标注为'参考'"；原型引用卡片**没有**该标注
- **影响**：若要标注，需要解析回答文本中的 `[n]` 来判断"是否被引用"，这属于新增的文本后处理能力，会影响 M5 的职责与验收方式。
- **结论（2026-11-01）**：采用 **A**——本期不区分，引用卡片统一展示"引用来源"，不标"参考"，也不解析回答中的 `[n]`。
- **连带影响**：M5 职责收敛为"组装引用卡片"，不含引用判定；SRS FR-5 中"标注为参考"一句需删除或降级为后续版本需求。

### Q7【已确认】无结果/生成失败时是否写入历史

- **出处**：SRS [FR-6](../SRS.md#fr-6-问答历史)"本期不保存'生成失败'的空回答"；但**无检索结果**时的固定话术是否算一次问答，未明确
- **影响**：用户是否会看到一堆"无法回答"的历史记录。
- **结论（2026-11-01）**：采用 **A**——检索无结果时**也保存**历史（回答是固定话术，属于有效问答）；仅"生成失败"（大模型异常、无回答文本）不保存。
- **连带影响**：历史里会出现"根据已有资料无法回答"的记录，本期不做筛选或折叠。

### Q8【已确认】单次超过 20 个文件的处理方式

- **出处**：SRS [BR-8](../SRS.md#9-业务规则)"单次 ≤ 20 个文件"，未说明超出如何处理；原型做法是截断前 20 个并提示
- **结论（2026-11-01）**：采用 **B**——**整批拒绝**，提示超出上限，本次一个文件都不处理，要求用户重新选择。
- **连带影响**：与原型原行为不同（原型曾是"截断前 20 个"），**v0.7 已同步修改原型**（`prototype/app.js` 的 `handleFiles` 改为整批拒绝）；M1 的前置校验增加一条"整批数量校验"，且该校验先于逐文件校验执行。

### Q9【已确认】表格类文档（xlsx/csv）的位置怎么显示

- **出处**：SRS [FR-5](../SRS.md#fr-5-引用来源) 只规定了"PDF 页码 / 无页码显示全文"，未覆盖 xlsx/csv
- **结论（2026-11-01）**：采用 **A**——统一显示"全文"，不区分工作表与行号。
- **连带影响（v0.7 落地）**：原型 `formatPage()` 原先对 `Sheet1!12` 这类值原样输出，已改为「非纯数字一律显示"全文"」；入库侧 `loaders.py` 仍把 `Sheet1!行号` 写进 `page`，由引用组装层统一映射。

### Q10【已确认】空知识库时的引导是否保留

- **出处**：SRS [FR-4](../SRS.md#fr-4-基于知识库的问答) 只要求"返回固定话术"；原型额外提供了"去上传文档"按钮与欢迎页示例问题（SRS 8.2 标注"可选"）
- **结论（2026-11-01）**：采用 **A**——**两者都保留**：固定话术 + "去上传文档"按钮 + 欢迎页示例问题，视为原型已确认的体验设计，不按新增功能处理。
- **连带影响**：SRS 8.2 中"示例问题（可选）"的标注可去掉；欢迎页示例问题需给出固定文案（建议沿用原型 4 条）。

### Q11【已确认】引用位置与文件类型的口径统一

- **出处**：SRS [6.1](../SRS.md#61-documents新增) 的 `file_type` 只列 pdf/docx/md/txt，而 [FR-1](../SRS.md#fr-1-文档批量上传) / [BR-9](../SRS.md#9-业务规则) 支持 xlsx/csv
- **结论（2026-11-01）**：采用 **A**——六种格式全部作为正式类型（pdf / docx / md / txt / xlsx / csv）。
- **连带影响**：SRS 6.1 的 `file_type` 取值说明需补齐 xlsx/csv。

### Q12【已确认】检索/生成进行中，允许用户做哪些操作

- **出处**：SRS 未明确；原型做法：生成中禁止提问、禁止切换历史、禁止删除历史（toast 提示"回答生成中，请稍候"），但**允许**切到知识库页
- **结论（2026-11-01）**：采用 **A**——沿用原型规则：生成中**整体只读**，仅允许切到知识库页；提问、切换历史、删除历史、新建对话一律拦截并提示。
- **连带影响**：该规则需写入界面需求（SRS 8.4 状态表），原型行为确认为本期范围。
