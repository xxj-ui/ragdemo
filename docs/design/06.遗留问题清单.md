## 6. B9：后端目录整理（2026-11-02）

**动因**：`server/` 根目录堆了 12 个散文件（装配件 + 两个仓储 + 四个工具），目录只有 `rag/`、`routes/`、`service/` 三个，与文档写的"四层"对不上，读代码时看不出框架。

**结果**：根目录只剩 2 个入口，职责收进 5 个目录。

| 现在 | 之后 |
| --- | --- |
| `config.py` `errors.py` `logging_conf.py` `timeutil.py` `storage.py` | `core/`（`logging_conf` → `logging`） |
| `document_repository.py` / `conversation_repository.py` / `rag/chunk_repository.py` | `db/documents.py` / `db/conversations.py` / `db/chunks.py` |
| `schemas.py` `deps.py` `routes/` | `api/schemas.py` `api/deps.py` `api/routes/` |
| `service/*` | `services/*`（去掉 `_service` 后缀） |
| `rag/cli.py` | 并入 `server/main.py` |
| `rrf.retrieve()` `keyword_search.search_chunks()` | 上移到 `services/retrieval.py`（内核不再查库） |
| 连接池创建（原在 `deps.py` 内） | `db/pool.py` |

**顺带修的边界问题**：`rag/` 之前既有 SQL（`chunk_repository`）又有整条检索链路（`retrieve` / `search_chunks`），与 `services/` 撞车；整理后 `rag/` 只保留纯算法（实测 `grep` 0 处 `psycopg` / `fastapi` 引用）。

**整理中引入并当场修掉的 bug**：`core/config.py` 的 `PROJECT_ROOT` 原本是 `parents[1]`，文件从 `server/config.py` 挪到 `server/core/config.py` 后就会指到 `server/`，上传文件会静默写进包目录、`stored_path` 也存成相对 `server/` 的路径。已改为 `parents[2]`，并加启动断言（项目根没有 `requirements.txt` 直接抛错），实测 `stored_path = data/uploads/<uuid>.txt` 落在项目根、`server/` 内不再生成 `data/`。

**回归**：20 项接口断言全通过 + 5 项落盘路径断言；CLI 预览 / `--build`（同文件二次入库 `doc_id` 不变）；`services/retrieval.retrieve()` 实测命中（`routes=dense+bm25`，RRF 0.0328）；8 条 `/api` 路由不变。

**新增文档**：[server/README.md](../../server/README.md)——目录树、依赖方向、"一次上传请求的旅程"、四条放置口诀。

| 项 | 结果 |
| --- | --- |
| SSE 事件序列 | `citations` → `delta`×10~25 → `done`（有命中）；`delta`+`done`（无命中） |
| 时延 | citations 1.07 s、首字节 1.64 s、全流 1.78 s（热态） |
| 引用 | `n` 从 1 连续、`filename`=原文件名、`page="全文"`、`snippet` 100 字、`chunk_id` 可追溯 |

| 不变量 I-4 | 每个会话恰 1 问 1 答（SQL 校验 0 异常） |
| 失败路径 | Key 缺失 / 超时 → `error` 事件且**不落库**；空库 → 固定话术且**仍落库** |
