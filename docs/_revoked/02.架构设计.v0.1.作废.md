### 1.2 依赖规则（编码阶段强制）

| 规则 | 说明 |
| --- | --- |
| R-1 | `routes → service → repository/内核`，单向；`ragdemo` 包**不得** import `server` |
| R-2 | SQL 只出现在 repository 层；service 只调用仓储方法与内核函数 |
| R-3 | 路由层只做三件事：解析/校验入参、调用 service、组装响应（含 SSE 事件编码） |
| R-4 | 内核模块（loaders / splitter / embedder / llm / rrf）保持无 Web 依赖，CLI（`main.py`）继续可用 |
| R-5 | 跨层传递用 dict / pydantic 模型，不把 psycopg 的 cursor / connection 传出去 |

## 2. 关键时序

### 2.1 上传入库（单文件）

```text
前端                    routes            service                    内核/DB
 │  POST /upload (1 文件) │                  │                          │
 ├──────────────────────►│ 校验 Content-Type │                          │
 │                       ├─────────────────►│ ① 扩展名白名单            │
 │                       │                  │ ② 流式落临时文件（计 50MB）│
 │                       │                  │ ③ 文件名清洗              │
 │                       │                  ├─────────────────────────►│ loaders.load
 │                       │                  │◄─────────────────────────┤ 解析为空 → 抛
 │                       │                  ├─────────────────────────►│ splitter
 │                       │                  ├─────────────────────────►│ embedder（线程池）
 │                       │                  │                          │
 │                       │                  │ ④ 事务：upsert documents ─┤
 │                       │                  │    delete chunks by doc_id│
 │                       │                  │    insert 新 chunk        │
 │                       │                  │    update chunk_count/at  │
 │                       │                  │◄──────── commit ─────────┤
 │                       │                  │ ⑤ os.replace 临时文件→正式 │
 │                       │                  │ ⑥ bm25 索引 invalidate    │
 │◄──────────────────────┤ items[{status:success, chunks, overwritten}]│
```

**失败语义**（对应 SRS FR-1 / BR-2 / BR-10）

| 失败点 | 处理 |
| --- | --- |
| ① 校验失败 | 不落盘、不入库，返回 `status=failed` + 原因（HTTP 200） |
| ② 超过 50 MB | 删除临时文件，`status=failed` |
| ③ 非法文件名 | 拒绝，`status=failed` |
| loaders 解析为空（扫描件 / 空表格） | 删除临时文件，`status=failed`，提示"可能是扫描件或空文档" |
| 嵌入失败 / DB 异常 | 回滚事务 + 删除临时文件，`status=failed` |
| ④ 事务成功、⑤ 替换文件失败 | 记录 error 日志；旧文件保留，`stored_path` 指向新路径 → **视为失败并回滚 DB**（见 ADR-09 的补偿顺序） |
| ⑥ invalidate 失败 | 不影响本次结果，日志告警，下次检索前会重建 |

**加锁**：所有入库与删除走同一个 `asyncio.Lock`（单进程内），避免同名文件并发上传互相覆盖。

### 2.2 问答（SSE）

```text
前端                 routes            chat_service            检索/LLM
 │ POST /api/chat      │                   │                     │
 ├────────────────────►│ 校验 1~500 字      │                     │
 │                     ├──────────────────►│ retrieve(20/20, k=60)│
 │                     │                   ├────────────────────►│
 │                     │                   │◄─ 5 条 或 空 ────────┤
 │                     │                   │                     │
 │                     │   ┌───────────────┴───────────────┐     │
 │                     │   │ 无结果                        │     │
 │                     │   │  session.create()             │     │
 │◄────────────────────┤   │  event: citations [] (空)     │     │
 │◄────────────────────┤   │  event: delta 固定话术        │     │
 │◄────────────────────┤   │  event: done {conversation_id}│     │
 │                     │   └───────────────────────────────┘     │
 │                     │   ┌───────────────┴───────────────┐     │
 │                     │   │ 有结果                        │     │
 │                     │   │  citations = M5(资料)         │     │
 │◄────────────────────┤   │  event: citations             │     │
 │                     │   │  session.create(先占位)       │     │
 │                     │   ├──────────────────────────────►│ llm.chat_stream
 │◄────────────────────┤◄──┤  event: delta × N             │     │
 │                     │   │  session.finish(回答+引用快照) │     │
 │◄────────────────────┤◄──┤  event: done {conversation_id}│     │
 │                     │   └───────────────────────────────┘     │
```

**异常与断开分支**

| 场景 | 事件 / 行为 | 历史 |
| --- | --- | --- |
| LLM 超时（60s） | `event: error {code: LLM_TIMEOUT}` | 不保存 |
| LLM 网络 / 5xx（SDK 已重试 2 次） | `event: error {code: LLM_UPSTREAM_ERROR}` | 不保存 |
| 缺 `DEEPSEEK_API_KEY` | `event: error {code: LLM_KEY_MISSING}` | 不保存 |
| 检索阶段 DB 不可用 | HTTP 503 `DB_UNAVAILABLE`（未进流，用普通 JSON 错误） | 不保存 |
| 两路均空（知识库为空或未命中） | 固定话术 + `done` | **保存**（SRS FR-6 / Q7） |
| 客户端断开（关标签 / 取消） | 生成器被取消 → 关闭 LLM 流 | 不保存 |

**SSE 编码约定**：`event: <name>\n data: <单行 JSON>\n\n`；JSON 用 `ensure_ascii=False`；`X-Accel-Buffering: no` 与 `Cache-Control: no-cache` 两个响应头固定下发。检索阶段（1~3s 无事件）前端本地显示"正在检索"，**不新增 `searching` 事件**（不扩大 SRS 7.4 契约）。

## 3. 数据架构与迁移

### 3.1 DDL 要点

DDL 是本节的交付物，约束如下：

- 全部表自增主键 `bigserial`，命名 `snake_case`，时间字段 `created_at` / `updated_at`（`timestamptz`，UTC 存储，展示层转本地）。
- **不建物理外键**（SRS D-9）：`rag_chunks.document_id`、`messages.conversation_id` 只是逻辑关联，配普通索引。
- 唯一性：`documents.filename` 用 `UNIQUE INDEX ON documents (lower(filename))`，与 Windows 大小写不敏感一致（SRS 6.1）。
- 列表索引：`documents (updated_at DESC)`；`messages (conversation_id, created_at)`；保留 `rag_chunks` 现有 HNSW 索引。
- 向量维度固定 512，`vector(512)`，与 bge-small-zh-v1.5 一致。
- 所有 DDL 幂等：`CREATE ... IF NOT EXISTS` / `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，可重复执行。

DDL 全文（M1 时原样落盘为 `migrations/001_init.sql`，作为**唯一 DDL 来源**；现有 `chunk_repository.init_table()` 退化为测试辅助，不再承担建表职责）：

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 文档
CREATE TABLE IF NOT EXISTS documents (
    id           bigserial   PRIMARY KEY,
    filename     text        NOT NULL,
    stored_path  text        NOT NULL,
    file_type    text        NOT NULL,
    file_size    bigint      NOT NULL,
    chunk_count  integer     NOT NULL DEFAULT 0,
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS documents_filename_lower_uidx
    ON documents (lower(filename));          -- 大小写不敏感同名覆盖（BR-1）
CREATE INDEX IF NOT EXISTS documents_updated_at_idx
    ON documents (updated_at DESC);          -- 列表排序（FR-2 / Q5）

-- 知识片段：在既有表上扩展，不重建
CREATE TABLE IF NOT EXISTS rag_chunks (
    id          bigserial    PRIMARY KEY,
    source      text         NOT NULL,
    page        text,
    chunk_index integer,
    content     text         NOT NULL,
    embedding   vector(512)
);
CREATE INDEX IF NOT EXISTS rag_chunks_embedding_idx
    ON rag_chunks USING hnsw (embedding vector_cosine_ops);
ALTER TABLE rag_chunks ADD COLUMN IF NOT EXISTS document_id bigint;   -- 逻辑关联（D-9）
CREATE INDEX IF NOT EXISTS rag_chunks_document_id_idx
    ON rag_chunks (document_id);

-- 会话
CREATE TABLE IF NOT EXISTS conversations (
    id         bigserial   PRIMARY KEY,
    title      text        NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS conversations_created_at_idx
    ON conversations (created_at DESC);

-- 消息
CREATE TABLE IF NOT EXISTS messages (
    id              bigserial   PRIMARY KEY,
    conversation_id bigint      NOT NULL,     -- 逻辑关联（D-9）
    role            text        NOT NULL CHECK (role IN ('user', 'assistant')),
    content         text        NOT NULL,
    citations       jsonb,                    -- 仅 assistant 使用，自包含快照（Q2）
    created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS messages_conversation_idx
    ON messages (conversation_id, created_at);
```

约定：
- 无 `FOREIGN KEY`（database-rules §4.2 / SRS D-9）；`role` 用 `CHECK` 限定取值（database-rules §3.6），这不是外键。
- 全部语句幂等，可重复执行；`DROP` 一律不写。
- 时区：`timestamptz` 存 UTC，接口层统一输出 `+08:00` 偏移（与 SRS 7.x 示例一致）。


### 3.2 表结构与设计 01 的对应

| 表 | 来源 | 备注 |
| --- | --- | --- |
| `documents` | SRS 6.1 | 新增 |
| `rag_chunks` | SRS 6.2 | 加 `document_id`、`stored_path` 无关；`source` 保留兼容 |
| `conversations` | SRS 6.3 | 新增 |
| `messages` | SRS 6.4 | 新增；`citations jsonb` 存自包含快照（Q2） |

### 3.3 迁移与旧数据

| 场景 | 方案 |
| --- | --- |
| 全新环境 | 启动时执行 `001_init.sql`（幂等），一次建全 |
| 已有 `rag_chunks` 旧数据（无 `document_id`） | **待裁决**，见 ADR-05：推荐清空重建（`TRUNCATE rag_chunks`），需你确认后执行 |
| 迁移工具 | 不引入 Alembic（单机单环境，见 ADR-06） |
| 回滚 | DDL 只增不删：`DROP COLUMN` 一律不做，回滚靠代码版本 |

### 3.4 事务边界

| 操作 | 事务范围 |
| --- | --- |
| 上传（覆盖） | 一个事务：upsert documents → delete chunks by doc_id → insert chunks → update 统计。文件替换在事务**外**，按 ADR-09 的补偿顺序 |
| 删除文档 | 一个事务：delete chunks by doc_id → delete documents 行；文件删除在事务**外**（失败只记日志） |
| 保存问答 | 一个事务：insert conversations → insert 两条 messages |
| 删除会话 | 一个事务：delete messages by conversation_id → delete conversations |

并发：单进程内 `asyncio.Lock` 串行化上传/删除；读取（列表、检索）不加锁。

## 4. 接口契约

### 4.1 统一响应

| 类别 | 结构 | 说明 |
| --- | --- | --- |
| 成功（单资源） | 直接返回资源对象 | 不套 `data` 壳，SRS 7.2 / 7.6 已如此定义 |
| 成功（列表） | `{"items": [...]}` | 本期不分页（SRS D-10） |
| 失败 | `{"detail": {"code": "...", "message": "..."}}` | `message` 中文可直接展示，`code` 稳定可判 |
| 参数校验失败 | FastAPI 原生 422 | 额外用异常处理器转成上面的 `detail` 结构 |

对 api-rules §4.1「统一成功和失败响应结构」的落地解释：**成功=资源本身、失败=detail 封装**，两者各自统一，不再额外套 `{code,data,meta}`。此解释写入 8.1 偏离登记。

### 4.2 错误码目录

| code | HTTP | 触发 | 用户可见文案 |
| --- | --- | --- | --- |
| `NO_FILE` | 422 | 请求没有文件字段 | 请选择要上传的文件 |
| `TOO_MANY_FILES` | 400 | 单次 > 20 个文件（整批拒绝） | 单次最多上传 20 个文件，请重新选择 |
| `FILE_TOO_LARGE` | 200¹ | 单文件 > 50 MB | 文件超过 50 MB |
| `UNSUPPORTED_FILE_TYPE` | 200¹ | 扩展名不在白名单 | 不支持的文件类型：.xxx |
| `EMPTY_FILE` | 200¹ | 0 字节 | 文件为空 |
| `INVALID_FILENAME` | 200¹ | 含路径分隔符或 `..` | 文件名非法 |
| `PARSE_EMPTY` | 200¹ | 解析结果为空 | 可能是扫描件或空文档 |
| `TABLE_EMPTY` | 200¹ | 表格无有效数据行 | 表格为空或无有效行 |
| `STORAGE_FAILED` | 500 | 落盘失败 | 文件保存失败，请重试 |
| `DB_UNAVAILABLE` | 503 | 连接 / 查询异常 | 数据库不可用，请检查服务 |
| `DOCUMENT_NOT_FOUND` | 404 | 删除不存在的文档 | 该文档已删除 |
| `QUESTION_EMPTY` | 422 | 问题为空 | 请输入问题 |
| `QUESTION_TOO_LONG` | 422 | 问题 > 500 字 | 问题不能超过 500 字 |
| `CONVERSATION_NOT_FOUND` | 404 | 历史不存在 | 该记录已删除 |
| `LLM_KEY_MISSING` | 500² | 未配置 Key | 未配置大模型 API Key |
| `LLM_TIMEOUT` | 504² | 60s 未完成 | 大模型响应超时，请重试 |
| `LLM_UPSTREAM_ERROR` | 502² | 上游 5xx / 网络错误 | 大模型服务异常，请重试 |
| `INTERNAL_ERROR` | 500 | 未分类异常 | 服务内部错误，请查看日志 |

¹ 文件级失败按 SRS 7.1 走 HTTP 200 + `items[].status=failed`，`code` 作为该条目的附加字段下发（新增字段，向后兼容；需评审确认，见 8.2）。
² 这三类发生在 SSE 流内，用 `event: error` 下发，不体现在 HTTP 状态码。

### 4.3 SSE 事件状态机

```text
        ┌──────────── error ──────────────┐
        │                                 │
start ──┴─► citations ──► delta* ──► done
                │                       ▲
                └──── 无结果：delta(固定话术) ─┘
```

| 事件 | 时机 | data |
| --- | --- | --- |
| `citations` | 检索完成、开始生成前（**必发一次**，无结果为 `[]`） | `{"items":[{n,filename,page,snippet,chunk_id}]}` |
| `delta` | LLM 每个增量 | `{"text": "..."}` |
| `done` | 正常结束 | `{"conversation_id": 15}` |
| `error` | LLM 类失败 | `{"code": "...", "message": "..."}` |

约束：
- 事件顺序固定，`done` 与 `error` **互斥**且必居其一。
- `citations` 编号在调用 LLM 前确定，流中不得变更（F-20）。
- 无结果路径不调 LLM，但事件序列与正常路径一致（`citations [] → delta 固定话术 → done`），前端无需分支。
- 生成中的历史保存发生在 `done` 之前；保存失败降级为日志告警，仍发 `done`（避免用户看到"回答成功但报错"）。

### 4.4 接口清单（与 SRS 7.x 对齐）

| 方法 | 路径 | 说明 | 成功码 |
| --- | --- | --- | --- |
| POST | `/api/documents/upload` | 逐文件提交，`files` 字段 | 200 |
| GET | `/api/documents` | 全量列表，按 `updated_at` 倒序 | 200 |
| DELETE | `/api/documents/{id}` | 删除文档 + chunk + 原文件 | 204 |
| POST | `/api/chat` | SSE 问答 | 200 |
| GET | `/api/conversations?limit=&offset=` | 历史列表 | 200 |
| GET | `/api/conversations/{id}` | 历史详情（只读） | 200 |
| DELETE | `/api/conversations/{id}` | 删除会话 | 204 |
| GET | `/api/health` | 健康检查 | 200（**恒 200**） |

### 4.5 健康检查语义

| 字段 | 取值 | 判定依据 |
| --- | --- | --- |
| `database` | `ok` / `unavailable` | `SELECT 1`，1s 超时 |
| `embedding_model` | `loaded` / `loading` / `failed` | 进程内状态（lifespan 预热） |
| `llm_key` | `configured` / `missing` | 环境变量存在性 |
| `status` | `ok` / `degraded` | 全 ok → ok；任一异常 → degraded |

恒返回 200 的理由：前端要读分项做展示（G3 销项）；`degraded` 时若返 503，前端只能拿到错误体、拿不到"哪一项坏了"。见 ADR-08。

## 5. 运行时与部署

### 5.1 进程模型

| 项 | 决策 | 理由 |
| --- | --- | --- |
| Worker 数 | **固定 1** | BM25 索引在进程内存，多 worker 会各建一份且失效通知不同步（ADR-02） |
| 监听 | `127.0.0.1:8000` | SRS 2.4.1 / NFR-3 |
| 启动命令 | `uvicorn server.app:app --host 127.0.0.1 --port 8000 --workers 1` | 单 worker 显式写死，避免误加 |
| 静态资源 | 前端构建产物由 Vite dev server 或独立静态服务提供；`data/uploads/` **不**挂载任何静态路由 | NFR-3 |

### 5.2 模型加载时机

```text
lifespan 启动
  ├─ 建连接池 / 校验 DSN（失败 → 进程退出，见 ADR-03）
  ├─ 执行 migrations/001_init.sql（幂等）
  ├─ state.embedding = "loading"
  ├─ 提交后台任务：线程池加载 SentenceTransformer
  └─ 立刻开始接受请求（/api/health 报 loading，问答按钮显示"模型加载中"）

加载完成 → state.embedding = "loaded"，同步构建 BM25 索引
加载失败 → "failed"，/api/chat 直接返回 LLM/模型错误码，文档功能仍可用
```

BM25 索引：启动时构建一次（`fetch_all` + `BM25KeywordSearch`），上传 / 覆盖 / 删除后置 `dirty=True`，**下一次检索前**重建一次（懒重建，避免每次上传都全量重建）。

### 5.3 阻塞与线程模型

| 工作 | 执行位置 | 说明 |
| --- | --- | --- |
| HTTP 处理 | asyncio 事件循环 | 路由与 service 编排都是 `async def` |
| psycopg 调用（同步驱动） | `anyio.to_thread.run_sync` | 不阻塞事件循环 |
| 嵌入（CPU 密集） | 专用 `ThreadPoolExecutor(max_workers=1)` | 串行化，避免多请求抢 CPU（ADR-04） |
| 解析（PDF 等） | 专用线程池（同上） | pdfplumber 是 CPU/IO 混合 |
| LLM 流式读取 | 事件循环 + 异步迭代 | openai SDK 同步客户端在流上会阻塞 → 用 `to_thread` 包裹迭代器或改用 AsyncOpenAI |

> 说明：现有 `llm.py` 用同步 SDK，`chat_stream` 是同步生成器。服务层用 `asyncio.to_thread(next, gen)` 逐块取，或切换 `AsyncOpenAI`——后者更干净，见 ADR-10（待评审）。

## 6. 横切设计

### 6.1 异常体系

```text
AppError(code, message, http_status)          # 基类
 ├─ ValidationError  (NO_FILE / QUESTION_EMPTY / ...)
 ├─ NotFoundError    (DOCUMENT_NOT_FOUND / CONVERSATION_NOT_FOUND)
 ├─ ConflictError    (TOO_MANY_FILES)
 ├─ UpstreamError    (LLM_TIMEOUT / LLM_UPSTREAM_ERROR / LLM_KEY_MISSING)
 ├─ StorageError     (STORAGE_FAILED)
 └─ DatabaseError    (DB_UNAVAILABLE)
```

全局处理器把 `AppError` 转成 `{"detail": {"code", "message"}}`；未捕获异常统一 `INTERNAL_ERROR` 500，日志带堆栈但响应不带。

### 6.2 超时与重试

| 依赖 | 超时 | 重试 |
| --- | --- | --- |
| DB 连接 | 5s | 不重试（快速失败 → 503） |
| 检索（稠密 + BM25 + RRF） | 10s 预算 | 不重试 |
| LLM | 60s（SDK `timeout`） | SDK 自带 2 次（仅连接类错误） |
| 嵌入（单文件） | 无硬超时，受上传整体时长约束 | 不重试 |

检索超出预算 → 503 `DB_UNAVAILABLE`（本期不做超时降级到单路召回）。

### 6.3 幂等

| 操作 | 幂等性 |
| --- | --- |
| 上传 | 同名覆盖天然幂等；重复上传同一文件结果一致（updated_at 变化） |
| 删除文档 | 首次 204，再次 404（前端按"已删除"提示，不报错） |
| 删除会话 | 同上 |
| 保存问答 | 每请求一次，不做去重 |

### 6.4 安全

| 项 | 措施 |
| --- | --- |
| 监听 | 仅 `127.0.0.1` |
| 文件名 | 只取 `Path(name).name`；拒绝含 `..`、`/`、`\`、控制字符；落盘名用 `uuid4().hex + 原扩展名` |
| 扩展名 | 白名单 `.pdf/.docx/.md/.txt/.xlsx/.csv`，再校验能否被对应 loader 解析 |
| 大小 | 流式读，超过 50 MB 立即中断并删除临时文件 |
| 路径穿越 | `stored_path` 由服务端生成，永远不含用户输入 |
| 密钥 | 只在 config 读取，日志与响应绝不回显 |
| 上传目录 | `data/uploads/`，不在任何静态挂载范围 |

### 6.5 前端架构（React + Vite + TS，ADR-07）

```text
src/
  api/            client.ts（fetch 封装 + 错误码→文案）、chatStream.ts（SSE 解析）
  state/          chatStore.ts（状态机）、docsStore.ts、healthStore.ts
  pages/          ChatPage / DocumentsPage
  components/     MessageList / CitationCard / Composer / UploadQueue / DocTable /
                  StatusPill / ConfirmModal / Toast
  hooks/          useChatStream / useDocuments / useHealth
```

**问答状态机**（G1 / G2 / G3 在此销项）：

```text
idle ──提交──► searching ──citations──► streaming ──done──► idle
   ▲                │                       │
   │                └── http 503/4xx ───────┴── event:error ──► failed
   │                                                             │
   └──────────────── 重试（重发同一问题） ◄────────────────────────┘

全局（与上面正交）：modelState = loaded | loading | failed    ← 来自 /api/health
                  serviceState = ok | degraded | unavailable  ← 同上
```

| 状态 | 界面行为 | 对应缺口 |
| --- | --- | --- |
| `searching` | 输入禁用、显示"正在检索知识库" | SRS 8.4 |
| `streaming` | 增量渲染 + 光标；整体只读，仅允许切知识库页 | Q12 |
| `failed` | 错误文案 + 「重试」按钮（重发原问题，不新增历史） | **G1** |
| `modelState=loading` | 输入框占位提示"模型加载中"，发送按钮禁用 | **G2** |
| `serviceState=degraded/unavailable` | 顶部徽标转黄/红，标题给出哪一项异常 | **G3** |

SSE 用 `fetch` + `ReadableStream` 手写解析（`EventSource` 不支持 POST body）；取消用 `AbortController`，对应服务端"客户端断开即停止生成"。

## 7. 架构决策记录（ADR）

> 每条：背景 / 候选 / 结论 / 影响 / 放弃理由。标「待裁决」的条目需你确认后才落地。

### ADR-01 分层与包结构
- **背景**：内核是 CLI 形态，需要加 Web 层，且 AGENTS.md 要求 routes → service → core 单向依赖。
- **候选**：A 全塞进 `ragdemo/` 一个包；B 新建 `server/` 包，`ragdemo/` 保持纯内核。
- **结论**：B。`ragdemo` 不 import `server`，CLI 继续可用。
- **影响**：多一个包；`ragdemo` 内新增 config/errors 两模块被两边共用。
- **放弃 A**：内核会被 Web 依赖污染，CLI 与测试都得带 FastAPI。

### ADR-02 BM25 索引生命周期
- **背景**：现 `rrf.retrieve` 每次查询都 `fetch_all` + 重建（`rrf.py:95`，每次请求多一次全表读；耗时量级为**推断**，未实测）；SRS BR-4 要求"失效后下次检索前重建"。
- **候选**：A 每次查询重建（现状）；B 启动建一次 + 写操作置 dirty + 检索前懒重建；C 增量更新索引。
- **结论**：B，且进程固定单 worker。
- **影响**：首次检索最慢（重建一次），之后常驻内存；删除/上传后第一次问答会慢 100~300ms。
- **放弃 A**：与 BR-4 不符且每次都付成本。**放弃 C**：增量维护 df/avgdl 在大改文档时更易出错，收益不抵复杂度。

### ADR-03 数据库连接串来源
- **背景**：`chunk_repository.py:12` 有明文密码，违反 SRS 2.4.3。
- **候选**：A 保留默认值但改成无密码；B 无默认值，缺失即启动失败；C 读 `.env` 文件（python-dotenv）。
- **结论**：B + 可选 `.env`（C 作为便利手段，不引入新依赖：用 `os.environ` + 启动脚本 `set`）。若你希望 `.env` 开箱可用，需批准新增 `python-dotenv`。
- **影响**：本地每次启动前要设 `RAG_DB_DSN`；启动脚本里写死示例（不含真实密码）。
- **放弃 A**：留默认值等于留一个错误配置的巨大陷阱。

### ADR-04 阻塞与并发
- **背景**：同步 psycopg + CPU 嵌入，直接放 async 路由会卡事件循环；NFR-1 要求 50 页 PDF ≤60s。
- **候选**：A 全同步（`def` 路由，FastAPI 自动丢线程池）；B async 路由 + `to_thread` + 专用单线程池做嵌入；C 上 Celery/队列异步化。
- **结论**：B。上传语义仍是同步返回（SRS 5.2），但 CPU 段串行化。
- **影响**：并发上传会排队（单用户场景可接受）；`/api/health` 在重活期间可能延迟几秒。
- **放弃 C**：引入中间件 + 轮询接口，超出本期范围。

### ADR-05 旧 chunk 数据回填 —— **待裁决**
- **背景**：`rag_chunks` 已有数据无 `document_id`；`documents` 表要求 `stored_path`、`file_size` NOT NULL，而老数据没有原文件。
- **候选**：
  - A **清空重建**：`TRUNCATE rag_chunks`，用新流程重新上传。简单、状态干净，但**删除既有机密数据**。
  - B **按 source 回填**：为每个 source 造 `documents` 行（`stored_path` 置空串、`file_size` 置 0），`UPDATE rag_chunks SET document_id=...`。保留数据，但列表里会出现"大小 0、无原文件"的文档，删除时也无文件可删。
  - C **混合**：回填但把 `stored_path`/`file_size` 改为可空（`documents` 表放宽约束）。
- **推荐**：A（当前是开发环境，数据可由 CLI 重新 `--build`；B 会留下永久脏数据）。
- **影响**：A 需你明确同意；C 会让表约束变松，后续新数据失去非空保护。
- **状态**：**未执行**，等你裁决。

### ADR-06 迁移工具
- **背景**：需要建表 + 加列。
- **候选**：A Alembic；B 单个幂等 SQL 文件 + 启动时执行。
- **结论**：B。
- **影响**：无版本表、无 downgrade；靠"只增不删"的约定保证可重复执行。
- **放弃 A**：单机单环境、无多人协作、无回滚需求，引入 Alembic 的配置成本大于收益。

### ADR-07 前端路线
- **背景**：SRS 定 React + Vite + TS，原型是原生 JS。
- **结论**：按 SRS（已由你于 2026-11-02 确认）。原型作为交互蓝本，组件与状态迁移到 React，异常态按第 6.5 节状态机补齐。
- **影响**：M3 需要新建前端工程；原型不再演进（只作参照）。
- **放弃"承接原生 JS"**：改 SRS 的代价大于新建工程，且流式渲染与状态机在 React 里更可控。

### ADR-08 健康检查恒返 200
- **背景**：`degraded` 时 HTTP 语义上可以是 503。
- **候选**：A 恒 200 + `status` 字段；B degraded 返 503。
- **结论**：A。
- **影响**：监控无法只靠状态码，需要读 body。
- **放弃 B**：前端拿不到分项明细（G3 无法销项）；且单用户场景没有依赖状态码的调用方。

### ADR-09 上传"新数据就绪后再替换"的实现
- **背景**：BR-2 要求"新数据未就绪前不得触碰旧数据"，但 DB 事务与文件系统无法真正原子。
- **候选**：A 先删旧文件再写新文件（违反 BR-2）；B 新文件先落最终路径（新 uuid，不与旧同名）→ DB 事务 → 成功后删旧文件；C 备份旧文件再覆盖。
- **结论**：B。旧文件在全流程中**不被覆盖**，只在新数据提交后被删除。
- **影响**：极端情况下（DB 成功、删旧失败）会留下孤儿文件，靠日志清理，不影响一致性。
- **放弃 C**：多一份磁盘副本与回滚逻辑，收益不明显。

### ADR-10 LLM 调用改异步 —— **待评审**
- **背景**：现有 `llm.py` 用同步 `OpenAI`，在 async 服务里流式迭代会阻塞事件循环。
- **候选**：A 用 `asyncio.to_thread(next, gen)` 逐块取；B 改用 `AsyncOpenAI` + `async for`。
- **推荐**：B（`AsyncOpenAI` 与现有 SDK 同包，改动集中在 `llm.py`）。
- **影响**：`llm.py` 的 `chat_stream` 变成 async 生成器，CLI 调用点需改 `asyncio.run`。
- **待评审**：会动已验证的内核文件，需要你确认是否允许修改 `llm.py` 的公开签名。

## 10. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 单 worker 下 CPU 嵌入期间健康检查变慢 | 前端误判服务不可用 | 健康检查不查模型、只查状态位；前端容忍 2 次失败再置 degraded |

| SSE 中间层缓冲 | 流式变"一次性" | 固定下发 `Cache-Control: no-cache`、`X-Accel-Buffering: no` |
