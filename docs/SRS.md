## 1. 引言

### 1.1 目的

本文档定义知识库问答系统的功能需求、非功能需求、数据模型、接口约定与验收标准，作为开发、测试和验收的依据。

系统在已有 RAG 核心（加载、切分、向量化、pgvector 存储、BM25 检索、RRF 融合、DeepSeek 生成）之上，增加 Web 界面与后端 API，使用户可以通过浏览器批量管理文档并基于知识库提问。

### 1.2 范围

**本期包含**

- 本机单用户 Web 应用（无登录）
- 文档批量上传、列表查看、整份删除
- 支持 PDF、DOCX、Markdown、TXT、XLSX、CSV 六种格式（不含扫描件）
- 同名文档覆盖更新
- 基于知识库的单轮问答
- 流式回答（SSE）与引用来源展示
- 问答历史保存与回看

**本期不包含**

- 多用户、注册登录、权限与数据隔离
- 扫描版 PDF / 图片 OCR
- 多轮对话上下文与查询改写
- 文档版本管理与回滚
- 公网部署、HTTPS、反向代理、容器化
- rerank 重排序模型
- 文档在线预览、编辑
- 移动端适配（桌面浏览器优先）
- 按单份文档筛选问答范围

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 知识库 | 本系统中所有已入库文档及其 chunk 的集合 |
| 文档 | 用户上传的一个文件（PDF / DOCX / MD / TXT / XLSX / CSV） |
| chunk | 文档经切分后入库的最小检索单元 |
| 稠密检索 | 用 embedding 向量 + pgvector 余弦相似度召回 |
| 关键词检索 | 用 jieba 分词 + BM25 召回 |
| RRF | Reciprocal Rank Fusion，按排名融合两路召回结果 |
| 引用 | 回答中 `[n]` 编号对应的知识库片段 |
| 会话 | 一次提问及其回答的记录（本期一次问答 = 一个会话） |

### 1.4 参考

- 现有代码：`server/rag/` 子包内的 `loaders.py`、`splitter.py`、`embedder.py`、`keyword_search.py`、`rrf.py`（片段读写已移到 `server/db/chunks.py`）、`llm.py`
- 嵌入模型：`BAAI/bge-small-zh-v1.5`（512 维，本地缓存）
- 大模型：DeepSeek `deepseek-chat`（OpenAI 兼容协议）
- 向量库：PostgreSQL + pgvector

## 2. 总体描述

### 2.1 产品视角

```text
浏览器（React）
    │  HTTP / SSE
    ▼
FastAPI 服务（本机 127.0.0.1）
    │
    ├── 服务层 server/services/（上传、删除、检索、问答、历史）
    │
    ├── PostgreSQL + pgvector（documents / rag_chunks / conversations / messages）
    ├── 本地文件存储（上传的原文件）
    ├── 本地嵌入模型 bge-small-zh-v1.5
    └── DeepSeek API（问答生成）
```

### 2.2 用户特征

单一用户，在本机使用，具备基本的文件管理和浏览器操作能力，无需培训即可使用。

### 2.3 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 11（当前开发环境） |
| 浏览器 | Chrome / Edge 最近两个大版本，桌面端，宽度 ≥ 1280px |
| 后端 | Python 3.11+，FastAPI + Uvicorn |
| 前端 | Node.js 18+，React + Vite + TypeScript |
| 数据库 | PostgreSQL + pgvector（本机 Docker，端口 54328） |
| 模型缓存 | `HF_HOME=D:\models\huggingface` |
| 网络 | 可访问 DeepSeek API |

### 2.4 设计约束

1. 单用户、无认证，服务只监听 `127.0.0.1`，不对局域网或公网开放。
2. 大模型 API Key 只从环境变量读取，不得写入代码、数据库或前端资源。
3. 数据库连接串从环境变量 `RAG_DB_DSN` 读取，不硬编码密码。
4. 嵌入模型与查询向量必须使用同一模型、同一归一化方式（512 维）。
5. 不引入 OCR；无文字层的 PDF 页跳过并提示用户。
6. 所有用户可见文案使用中文。

### 2.5 假设与依赖

- pgvector 容器已启动，数据库可连接。
- DeepSeek API Key 已配置且账户有余额。
- 上传的 PDF 含文字层，不是扫描件。
- 知识库规模：几十份文档、chunk 总量不超过约 5000。
- 用户通过本机浏览器访问，不存在跨域与公网攻击面。

## 3. 功能需求

### FR-1 文档批量上传

**描述**：用户可一次选择或拖拽多个文件上传，系统解析、切分、向量化并入库。

**输入**

- 1～20 个文件
- 支持格式：`.pdf`、`.docx`、`.md`、`.txt`、`.xlsx`、`.csv`
- 单文件大小 ≤ 50 MB

**处理**

1. 校验扩展名、文件大小、文件名安全性。
2. 解析、切分（`size=500`、`overlap=100`）、向量化；任一步失败即停止处理该文件，不写入数据库、不保留原文件。
3. 解析、切分、向量化全部成功后，才一次性替换旧数据：写入新 chunk、更新 `documents` 记录、替换原文件；**新数据未就绪前不得触碰旧数据**。
4. 替换失败时旧数据与旧原文件保持原样，不得留下半成品。
5. 每个文件独立处理，单个失败不影响同批其他文件。
6. 入库完成后刷新 BM25 内存索引。

**输出**

每个文件返回处理结果：文件名、状态（成功 / 失败）、chunk 数、文档 ID、是否覆盖、失败原因。

失败的文件不写入 `documents` 表，也不保留在磁盘上；仅在上传结果中返回失败原因。

**异常**

| 场景 | 处理 |
| --- | --- |
| 单次超过 20 个文件 | 整批拒绝，提示数量上限，本次不处理任何文件 |
| 超过 50 MB | 该文件标记失败，提示大小上限 |
| 空文件（0 字节） | 该文件标记失败，提示“文件为空” |
| 解析结果为空（含扫描版 PDF） | 标记失败，提示“可能是扫描件或空文档” |
| 表格无有效数据行 | 标记失败，提示“表格为空或无有效行” |
| 文件名含路径分隔符或 `..` | 拒绝并提示非法文件名 |
| 数据库 / 模型异常 | 该文件标记失败，回滚本次写入 |
| 同名文件已存在 | 覆盖旧文档，返回“已覆盖”标识 |

**界面要求**

- 上传区支持点击选择和拖拽。
- 显示每个文件的处理状态与结果。
- 上传过程中禁止重复提交同一批文件；允许取消未开始的文件（可选）。

---

### FR-2 文档列表

**描述**：展示知识库中所有文档及其处理状态。

**字段**

文件名、文件类型、文件大小、chunk 数、最近更新时间。

**规则**

- 按最近更新时间倒序排列；同名文档被覆盖后，该文档浮到列表顶部。
- 每次进入知识库页或上传完成后自动刷新。
- 无文档时展示空状态与上传引导。
- 页面标题区展示文档总数与知识片段总数（导航徽标 + 标题区），随列表刷新。
- 列表只包含上传成功的文档；失败文件仅在本次上传结果中提示，不进入列表。

---

### FR-3 文档删除

**描述**：用户可删除整份文档，删除后该文档内容不再参与检索。

**处理**

1. 弹出二次确认，明确提示“将同时删除该文档的所有知识片段和原文件，且不可恢复”。
2. 删除 `documents` 记录及其全部 `rag_chunks`（级联）。
3. 删除本地存储的原文件。
4. 使 BM25 内存索引失效并在下次检索前重建。

**异常**

| 场景 | 处理 |
| --- | --- |
| 文档不存在 | 接口返回 404；前端按“已删除”友好提示，不展示错误态 |
| 原文件已被手动删除 | 仍删除数据库记录，返回成功 |
| 数据库删除失败 | 返回 500，不删除原文件，保持状态一致 |

---

### FR-4 基于知识库的问答

**描述**：用户输入问题，系统检索知识库并由大模型生成有依据的回答。

**输入**

- 问题文本，非空，长度 ≤ 500 字。

**处理流程**

1. 校验问题非空且未超长。
2. 两路召回：
   - 稠密检索：查询向量 + pgvector 余弦相似度，召回 20 条；
   - 关键词检索：jieba 精确分词 + BM25，召回 20 条。
3. RRF 融合（`k=60`），取前 5 条作为参考资料。
4. 若两路均无结果：不调用大模型，直接返回固定话术“根据已有资料无法回答”。
5. 若有结果：组装带编号的参考资料，调用 DeepSeek 流式生成回答。
6. 流式返回增量文本，并下发引用来源。
7. 生成结束后保存本次问答到历史记录。

**回答规则（系统提示词约束）**

- 只使用参考资料中的信息，不编造。
- 资料不足时回答“根据已有资料无法回答”。
- 引用处使用 `[编号]` 标注。
- 使用中文回答。

**异常**

| 场景 | 处理 |
| --- | --- |
| 问题为空 / 超长 | 前端拦截；后端返回 422 与明确提示 |
| 知识库为空 | 返回固定话术 + "去上传文档"引导按钮，不调用大模型 |
| DeepSeek 超时 / 网络错误 | 终止流，发送 error 事件，前端提示可重试 |
| API Key 缺失 | 返回配置错误提示，不泄露 Key |
| 数据库不可用 | 返回 503，提示检查数据库 |

---

### FR-5 引用来源

**描述**：回答下方展示本次回答引用的知识库片段。

**字段**

- 序号（与回答中的 `[n]` 对应）
- 文件名
- 位置（PDF 页码；DOCX/TXT/MD 无页码时显示“全文”）
- 片段摘要（前 100 字，超出以省略号截断）

**规则**

- 引用顺序与提供给大模型的资料编号一致。
- 本期不做"是否被实际引用"的判定，引用卡片统一展示为"引用来源"，不标注"参考"。
- 本期不支持点击展开完整 chunk 原文。

---

### FR-6 问答历史

**描述**：保存每次问答，用户可在侧边栏回看。

**规则**

- 每次提问创建一个会话，包含一条用户消息和一条助手消息。
- 会话标题取问题前 30 字，超出省略。
- 历史按时间倒序排列，最多展示最近 50 条，支持滚动加载更多（可选）。
- 点击历史项回看完整问题、回答与引用，不重新调用大模型。
- 支持删除单条历史；删除会话时一并删除其全部消息（服务层在同一事务内先删消息，再删会话）。
- 刷新页面或重启服务后历史仍存在。
- 本期不保存“生成失败”的空回答；失败仅在界面上提示。检索无结果（返回固定话术）属于有效问答，**仍需保存**。

---

### FR-7 系统状态

**描述**：前端可获知后端是否可用。

**要求**

- 提供健康检查接口，返回数据库连通性、嵌入模型是否已加载、DeepSeek Key 是否配置。
- 首次加载模型期间，前端问答按钮显示“模型加载中”，避免用户误以为卡死。

## 4. 非功能需求

### NFR-1 性能

| 指标 | 目标 |
| --- | --- |
| 检索耗时（热态，≤5000 chunk） | P95 ≤ 300 ms |
| 首字延迟（热态） | ≤ 3 s |
| 单个 50 页 PDF 入库 | ≤ 60 s（本机 CPU） |
| 文档列表接口 | ≤ 200 ms |
| 历史列表接口 | ≤ 200 ms |

冷启动（首次加载嵌入模型）允许额外 10 s 左右，界面上需有提示。

### NFR-2 可靠性

- 上传与删除操作幂等：重复执行不产生重复数据。
- 同名覆盖采用“先写新数据成功、再清理旧数据”或事务方式，失败时保留旧数据。
- 单个文件失败不阻断同批其他文件。
- 服务重启后，BM25 索引可从数据库重建，不依赖进程内状态。

### NFR-3 安全

- 服务仅监听 `127.0.0.1`。
- API Key 仅存于环境变量，不出现在日志、响应和前端。
- 上传文件按白名单校验扩展名，并校验实际可解析性。
- 文件名清洗，禁止路径穿越；存储时使用服务端生成的安全文件名。
- 上传目录不在前端静态资源可访问范围内。

### NFR-4 易用性

- 全中文界面。
- 所有异步操作有加载态，失败有明确原因。
- 删除操作必须二次确认。
- 输入框支持 Enter 发送、Shift+Enter 换行。

### NFR-5 兼容性

- Chrome / Edge 最近两个大版本。
- 桌面端 1280px 及以上；不保证移动端体验。

### NFR-6 可维护性

- API 路由、业务服务、RAG 核心分层，路由层不直接操作数据库。
- 检索参数（top_k、recall_k、RRF k）、切分参数、文件限制集中配置。
- 关键路径有日志：上传、删除、检索耗时、生成耗时、异常。

## 5. 系统架构

### 5.1 分层

```text
前端 React
  ├── 问答页（Chat）
  └── 知识库页（Documents）
        │
        ▼
FastAPI 路由层（server/api/routes/）
        │
        ▼
服务层 server/services/
  ├── upload_document(path) -> DocumentResult
  ├── list_documents() -> list[Document]
  ├── delete_document(id)
  ├── ask_stream(question) -> Iterator[Event]
  └── history 相关方法
        │
        ▼
RAG 核心（server/rag/ 子包内的纯 Python 模块）
  ├── loaders.py / splitter.py
  ├── embedder.py
  ├── db/chunks.py（片段读写，原 chunk_repository.py）
  ├── keyword_search.py（BM25，进程内缓存）
  ├── rrf.py
  └── llm.py
        │
        ▼
PostgreSQL + pgvector ／ 本地文件存储 ／ DeepSeek API
```

### 5.2 关键设计决策

| 决策 | 说明 |
| --- | --- |
| 单用户无认证 | 仅本机使用，省去鉴权与数据隔离 |
| 单轮问答 | 每次提问独立检索，不做历史上下文拼接与查询改写 |
| 同名覆盖 | 先完成新数据的解析、切分与向量化，再一次性替换旧 chunk 与原文件（见 BR-2） |
| 同步上传 | 规模小（≤5000 chunk），上传接口同步完成并返回结果 |
| SSE 流式 | 复用现有 `chat_stream`，提升等待体验 |
| BM25 内存索引 | 服务启动时构建，上传/删除后失效重建；规模上限内足够 |
| 原文件落盘 | 便于覆盖、审计与后续重建索引 |

## 6. 数据模型

### 6.1 documents（新增）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigserial | PK | 文档 ID |
| filename | text | NOT NULL, UNIQUE | 原始文件名（Windows 下按不区分大小写处理） |
| stored_path | text | NOT NULL | 服务端存储路径 |
| file_type | text | NOT NULL | pdf / docx / md / txt / xlsx / csv |
| file_size | bigint | NOT NULL | 字节数 |
| chunk_count | integer | NOT NULL DEFAULT 0 | chunk 数 |
| created_at | timestamptz | NOT NULL DEFAULT now() | 首次上传时间 |
| updated_at | timestamptz | NOT NULL DEFAULT now() | 最近覆盖时间 |

索引：`(updated_at DESC)`（列表按最近更新倒序，见 FR-2）。唯一性按不区分大小写处理：对小写化后的文件名建唯一约束。

### 6.2 rag_chunks（在现有表上扩展）

现有字段：`id`、`source`、`page`、`chunk_index`、`content`、`embedding vector(512)`。

新增字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| document_id | bigint | 逻辑关联 documents(id)，不建物理外键（D-9） |

索引：`(document_id)`；保留现有 HNSW 向量索引。`source` 保留用于展示与兼容旧数据。

删除文档时，服务层在同一事务内先 `DELETE FROM rag_chunks WHERE document_id = ?`，再删除 `documents` 记录，不依赖数据库级联。
已有 `rag_chunks` 旧数据（无 `document_id`）的回填方案在架构设计文档中确定。

### 6.3 conversations（新增）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | 会话 ID |
| title | text | 问题前 30 字 |
| created_at | timestamptz | 创建时间 |

### 6.4 messages（新增）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | 消息 ID |
| conversation_id | bigint | 逻辑关联 conversations(id)，不建物理外键（D-9） |
| role | text | user / assistant |
| content | text | 消息正文 |
| citations | jsonb | 引用列表，仅 assistant 消息使用 |
| created_at | timestamptz | 创建时间 |

索引：`(conversation_id, created_at)`。删除会话时，服务层在同一事务内先删该会话的全部消息，再删 `conversations` 记录。

### 6.5 citations JSON 结构

```json
[
  {
    "n": 1,
    "filename": "计算机网络.pdf",
    "page": "3",
    "snippet": "……前 100 字……",
    "chunk_id": 123
  }
]
```

## 7. 接口设计

统一前缀 `/api`。无认证。

**所有 JSON 响应同构三字段**：`code` + `message` + `data`（成功 `code="ok"`，失败为错误码；`data` 成功时为资源本体、失败时为 `null`）。

```json
// 成功
{ "code": "ok", "message": "ok", "data": { "items": [] } }

// 失败（HTTP 状态码仍表达类别：422 / 404 / 503 / 500）
{ "code": "UNSUPPORTED_FILE_TYPE", "message": "不支持的文件类型：.exe", "data": null }
```

唯一例外是 **7.4 的 SSE 事件**：`event:` 行已表达语义，事件 `data` 不套信封。错误码目录、参数校验与异常映射见 [04.API接口设计.md](design/04.API接口设计.md) §3.3~§3.5。

### 7.1 上传文档

`POST /api/documents/upload`

- Content-Type：`multipart/form-data`
- 字段：`files`（**每次请求恰好 1 个文件**；批量由前端循环提交）
- 一次请求只处理一个文件，按文件粒度返回结果；单文件失败仍返回 `200`，原因在 `data.items[0].error`

响应 `200`：

```json
// 成功
{
  "code": "ok",
  "message": "ok",
  "data": {
    "items": [
      { "filename": "计算机网络.pdf", "status": "success", "document_id": 1,
        "chunks": 37, "overwritten": false, "error": null }
    ]
  }
}

// 该文件失败（HTTP 仍 200）
{
  "code": "ok",
  "message": "ok",
  "data": {
    "items": [
      { "filename": "bad.exe", "status": "failed", "document_id": null,
        "chunks": 0, "overwritten": false,
        "error": { "code": "UNSUPPORTED_FILE_TYPE", "message": "不支持的文件类型：.exe" } }
    ]
  }
}
```

失败项不会产生 `documents` 记录，也不会保存原文件。

### 7.2 文档列表

`GET /api/documents`

响应 `200`：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "items": [
      {
        "id": 1,
        "filename": "计算机网络.pdf",
        "file_type": "pdf",
        "file_size": 1048576,
        "chunk_count": 37,
        "created_at": "2026-10-30T10:00:00+08:00",
        "updated_at": "2026-10-30T10:00:00+08:00"
      }
    ]
  }
}
```

说明：本期文档数量为几十份，列表返回全量、不分页，响应不含 `total` / `limit` / `offset`（对 api-rules §4.4 的明确豁免，见 D-10）。

### 7.3 删除文档

`DELETE /api/documents/{id}`

- 成功：`200`（信封 `{code:"ok", message:"ok", data:null}`）
- 不存在：`404`（前端按“已删除”友好提示，不展示错误态）
- 删除失败：`500`

### 7.4 问答（SSE）

`POST /api/chat`

请求体：

```json
{
  "question": "王教授在哪个教室上课？"
}
```

响应：`200`，`Content-Type: text/event-stream`

事件序列：

```text
event: citations
data: {"items": [{"n":1,"filename":"课程安排.pdf","page":"2","snippet":"……","chunk_id":12}]}

event: delta
data: {"text": "王教授"}

event: delta
data: {"text": "在 302 教室上课 [1]。"}

event: done
data: {"conversation_id": 15}

event: error
data: {"code": "LLM_TIMEOUT", "message": "大模型响应超时，请重试"}
```

说明：

- 无检索结果时，直接发送一段固定的 `delta` 与 `done`，不调用大模型。
- 客户端断开连接时，服务端应停止生成。
- `citations` 事件在大模型开始输出前发送；**无检索结果时不发送该事件**，只发 `delta` 与 `done`。
- SSE 事件的 `data` **不套** §7 开头的信封（全项目唯一例外）：事件名已表达语义，`error` 事件自带 `code`/`message`。

### 7.5 历史列表

`GET /api/conversations?limit=50&offset=0`

响应 `200`：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "items": [
      {"id": 15, "title": "王教授在哪个教室上课？", "created_at": "2026-10-30T10:05:00+08:00"}
    ]
  }
}
```

说明：`limit` 默认 50、最大 100；`offset` 从 0 开始；本期响应不返回 `total`（不提供总数与总页数）。

### 7.6 历史详情

`GET /api/conversations/{id}`

响应 `200`：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "id": 15,
    "title": "王教授在哪个教室上课？",
    "created_at": "2026-10-30T10:05:00+08:00",
    "messages": [
      {"role": "user", "content": "王教授在哪个教室上课？", "citations": []},
      {"role": "assistant", "content": "王教授在 302 教室上课 [1]。", "citations": [{"n":1,"filename":"课程安排.pdf","page":"2","snippet":"……","chunk_id":12}]}
    ]
  }
}
```

### 7.7 删除历史

`DELETE /api/conversations/{id}` → `200`（`data:null`）/ `404`

### 7.8 健康检查

`GET /api/health`

```json
{
  "code": "ok",
  "message": "ok",
  "data": { "status": "ok", "database": "ok", "embedding_model": "loaded", "llm_key": "configured" }
}
```

取值集合：`status` = `ok` | `degraded`；`database` = `ok` | `error`；`embedding_model` = `loaded` | `loading` | `failed`（冷启动期间为 `loading`）；`llm_key` = `configured` | `missing`。

任一项异常时 `status` 为 `degraded`，并注明具体项。本接口**恒返 200**（降级也用 200，靠字段表达）。

## 8. 界面需求

### 8.1 总体布局

- 顶部导航：应用名 + “问答” / “知识库” 切换；当前视图记录在 URL 锚点（`#chat` / `#docs`），刷新后保持。
- 问答页：左侧历史侧边栏（可折叠）+ 右侧消息区。
- 知识库页：上传区 + 文档表格。

### 8.2 问答页

- 输入框固定底部，支持 Enter 发送、Shift+Enter 换行。
- 用户消息与助手消息区分样式。
- 助手回答流式渲染；生成过程中显示光标或加载动画。
- 回答下方展示引用卡片：序号、文件名、位置、片段摘要。
- 无检索结果时展示固定提示。
- 生成失败时展示错误提示与“重试”按钮。
- 首次进入时若无历史，展示引导文案与示例问题（示例问题属本期范围）。

### 8.3 知识库页

- 上传区：点击选择或拖拽；显示支持格式与大小限制。
- 文件表格：文件名、类型、大小、chunk 数、上传时间、操作（删除）。
- 上传结果逐文件显示成功 / 失败及原因。
- 删除时弹出确认对话框。
- 空状态展示上传引导。

### 8.4 状态与反馈

| 状态 | 展示 |
| --- | --- |
| 上传中 | 文件行显示「处理中」（单态；同步上传不提供解析/切分/写入的阶段进度） |
| 模型冷启动 | 顶部或输入框提示“模型加载中” |
| 检索中 | 输入框禁用，显示“正在检索” |
| 生成中 | 流式文本 + 光标；提问、切换历史、删除历史、新建对话一律拦截并提示，仅允许切到知识库页 |
| 错误 | 明确错误原因，可重试 |

## 9. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-1 | 同名文件视为同一文档，上传即覆盖旧版本 |
| BR-2 | 覆盖时先完成新数据的解析、切分与向量化，再一次性替换旧 chunk 与原文件；任一步失败则旧数据与旧原文件保持原样 |
| BR-3 | 删除文档时，在同一事务内先删除其全部 chunk 记录、再删文档记录，并删除磁盘原文件（由服务层保证，不依赖数据库外键） |
| BR-4 | 上传与删除后，BM25 索引必须失效并在下一次检索前重建 |
| BR-5 | 每次问答独立检索，不携带历史上下文 |
| BR-6 | 检索无结果时不调用大模型，返回固定话术 |
| BR-7 | 引用编号按提供给大模型的资料顺序生成 |
| BR-8 | 单文件 ≤ 50 MB，单次 ≤ 20 个文件，问题 ≤ 500 字；单次超过 20 个文件时整批拒绝，要求重新选择 |
| BR-9 | 支持 `.pdf`、`.docx`、`.md`、`.txt`、`.xlsx`、`.csv`；旧版 `.doc`、`.xls` 不支持 |
| BR-10 | 上传失败的文件不写入文档表、不保留原文件，仅返回失败原因 |

## 10. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-1 | 上传一份含文字的 PDF | 列表出现该文档，chunk 数 > 0 |
| AC-2 | 上传同名但内容不同的 PDF | 列表仍只有一条记录，chunk 数更新，该文档排到列表首位，旧内容不再被检索到 |
| AC-3 | 上传 `.exe` 与一份正常 PDF | `.exe` 标记失败并说明原因，且不出现在文档列表；PDF 正常入库 |
| AC-4 | 删除一份文档 | 列表移除，检索不再命中，磁盘原文件被删除 |
| AC-5 | 提问知识库中存在的知识 | 流式输出中文回答，含 `[n]` 引用，引用卡片可对应到文件名 |
| AC-6 | 提问知识库中不存在的内容 | 返回“根据已有资料无法回答”，不调用大模型 |
| AC-7 | 刷新页面 | 历史记录仍存在，点击可回看原问题、回答与引用 |
| AC-8 | DeepSeek 不可用时提问 | 前端收到 error 事件并提示重试，不产生空历史记录 |
| AC-9 | 上传文件名为 `..\..\evil.pdf` | 被拒绝，不写入上传目录之外的位置 |
| AC-10 | 服务重启后提问 | BM25 与向量检索均正常，无需手动重建索引 |
| AC-11 | 问题为空或超过 500 字 | 前端阻止提交；直接调用接口返回 422 |
| AC-12 | 上传带表头的 xlsx | 成功入库，chunk 数 > 0，检索可按“列名: 值”命中表格内容 |
| AC-13 | 上传 0 字节的空文件 | 该文件标记失败并提示“文件为空”，不出现在文档列表，磁盘上不保留临时文件 |

## 12. 已确认决策与其余默认值

以下决策已在需求澄清中逐项确认：

| 编号 | 决策 |
| --- | --- |
| D-1 | 单用户、无登录、仅本机使用 |
| D-2 | 支持 PDF / DOCX / Markdown / TXT / XLSX / CSV，不做 OCR |
| D-3 | 同名文档覆盖；失败文件不入库、不落盘 |
| D-4 | 原文件保留，删除文档时一并删除 |
| D-5 | 单文件 ≤ 50 MB，单次 ≤ 20 个文件，问题 ≤ 500 字 |
| D-6 | 单轮问答；历史永久保留，支持删除单条；不做停止生成 |
| D-7 | 流式回答 + 引用来源，引用片段只展示前 100 字，不支持展开 |
| D-8 | 仅本机运行，不容器化、不开放局域网 |
| D-9 | 表间只建逻辑关联，不建物理外键；级联删除由服务层在同一事务内保证（与 database-rules 一致） |
| D-10 | 列表接口不分页：文档列表全量返回；历史列表支持 limit/offset 但不返回总数（对 api-rules §4.4 的明确豁免） |

其余按以下默认值实现，评审时如无异议即视为确认：

1. 同名判断不区分大小写（与 Windows 文件系统一致）。
2. 原文件存储于项目目录 `data/uploads/`，文件名由服务端生成。
3. 文档列表不提供搜索、分页与排序切换；几十份文档直接全量展示。
4. 引用卡片统一展示“引用来源”，不判定资料是否被实际引用，也不标注“参考”（Q6）。
5. 会话删除功能纳入本期（随 D-6）。
6. 现有 `loaders.py` 的 `.xlsm` 解析能力暂不开放界面入口，只开放 `.xlsx` / `.csv`。
7. 列表接口不采用统一分页结构（对 api-rules §4.4 的明确豁免，D-10）：文档列表返回全量且不分页；历史列表支持 `limit` / `offset`，但不返回总数。理由是单用户、几十份文档、历史最多回看 50 条，分页没有收益。

## 13. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上传的是扫描版 PDF | 解析为空，无法入库 | 明确提示不支持 OCR |
| CPU 嵌入较慢 | 大批量上传等待时间长 | 同步处理 + 前端逐个显示进度；限制单次数量 |
| 表格解析效果不稳定 | 复杂表头、合并单元格导致内容错乱 | 开放前补一组表格用例；必要时限制为简单表格 |
| 同名覆盖不可恢复 | 误覆盖导致旧文档丢失 | 二次确认；保留原文件备份（可选） |
| DeepSeek 网络或额度问题 | 无法生成回答 | 明确错误提示；保留检索结果便于重试 |
| 知识库增长超出预期 | 内存 BM25 变慢、启动变久 | 规模上限 5000 chunk；超出后评估 pg_search / Elasticsearch |
| 数据库或容器未启动 | 全部功能不可用 | 健康检查 + 启动文档说明 |
